## 2. 执行规则
1. 输入文件 `locked_cases.csv` 只能有 `case_id` 和 `text` 两列。先核对 SHA-256，与负责人登记的哈希一致才运行。
2. 运行前检查与开发集 86 条的精确重复：比对原文本身，以及去掉空白后的文本。命中的条目照常运行，但报告时单独标出。
3. **只运行一次**，只用 `scripts/run_locked_test.py`。不手动重新请求，不挑选结果。
4. 重试只限 Provider 内置的瞬时错误重试：5xx、QPS 或 TPM 类 429 错误，最多 2 次。每一次请求都记录在案。
5. 模型输出无效（无法解析，或不符合契约）时，经过冻结后处理 v2.3 的白名单修复后仍无效，就计为 **invalid**，留在所有分母里，**不改判为 clear**。
6. 运行结束后先封存预测：运行 `PREDICTIONS_SEALED.json`，再用 `verify_seal.py` 校验通过之后，才接收 PRIVATE_GOLD。

## 3. 指标（看到参考答案前就确定）
**主指标**：冻结系统（含后处理 v2.3）的四分类分流（flag / review / clear / unknown）与参考分类的一致率，并给出完整混淆矩阵（4 × 5，含 invalid 列）。

报告分三组，每一组都要报：
- 全部 30 条；
- 预先标记的 12 条争议案例；
- 另外 18 条案例。

次要指标：
- 每个类别的 P、R、F1；
- 输出通过校验的比例（修复前和修复后）；
- 引用为原文连续片段的比例；
- 后处理修复的次数和类型；
- 人工复核队列的 P 和 R（非 clear 都算进队列；这个指标不能叫“歧视识别率”）；
- 延迟的中位数和 P95；
- 调用次数和 token 用量；
- 基线 A、基线 B 的同样指标。

如果参考答案里有对应字段，还会报告：
- 核心性别、婚育线索的 P 和 R（参考 flag 且 reason 为 explicit_sex 或 marriage_birth 的才算阳性；照护、语境、unknown 单独报告）；
- scope 的一致率。

**参考答案为 unresolved（或等价的“未决”）的条目**：不计入确定性一致率，单独列出数量和模型输出。

**参考答案给出多个可接受分类时**：主指标按“首选分类”算，另外报告一个“落在可接受集合内”的比例。具体怎么认定首选和可接受集合，以参考文件的字段说明为准。对应字段的转换规则，会在**打开参考答案之前**根据法学方给的字段说明写好，打开后不再改。

## 4. 解释口径（同样提前确定）
- 参考分类来自单一法学本科研究者的首轮判断，部分字段由 GPT 辅助整理，**不是多专家法律金标准**。
- 12 条争议案例上出现不一致，**不等于模型法律错误**；报告时写“与参考分类不一致”，并附上争议记录的摘要（前提是允许公开）。
- 结果不能称为“律师认证准确率”或“法律准确率”。
- 样本量是 30，任何差异都不做统计显著性的说法；比例会同时写出分子和分母。
- 云端采样有随机性：单次运行的结果不代表模型的稳定表现，这一点要披露。
- 看到参考答案之后，不修改冻结系统再拿同一批案例称为独立测试。如果之后有修订，这 30 条一律改称开发集。
