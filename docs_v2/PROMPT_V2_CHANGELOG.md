## v2.0 相对 v1 的改动
1. 输出改为 `scope` + `findings[]` + `context_quotes` + `missing_facts` + `rationale`。模型不再输出 status、needs_human_review 和 confidence，这三项由程序推导或不提供。
2. 新增五类 reason 的定义：explicit_sex、marriage_birth、care_condition、context、exception_missing，并写明“照护条件不表示针对女性”。
3. 新增一张“本身不是线索”清单，覆盖：
   - 欢迎性表述（Round 1 E033 误报的原因）
   - 能力要求和工作安排
   - 角色与声部
   - 否定、引用和历史条件
   - 照护福利
4. 明确写出：前面的“男女不限”不能抵消后面的限制；每个条件单独列为一条 finding。
5. 防注入：用户文本放在 `<招聘文本>` 标签内，并声明其中的命令不执行。
6. 增加 3 个编造示例：多条件并存、否定性讲义、照护条件。
7. 生成参数：thinking 关闭，贪心解码，`max_new_tokens` 从 384 提高到 640，因为输出字段变多了。

## v2.1-2026-10-29（`rfl/prompt_v2_1.py`；v2.0 文件不改）

**触发原因**：v2.0 在开发集 86 条上的 9 个错误中，8 个是过度报警，1 个是无效输出。
- 角色/声部：E045、E047、R006、R007 被标成 explicit_sex。
- 欢迎性表述：E033、P03、R002。
- 培训：E049。
- 无效输出：S11 的键名写成了 `missing_fs`。

**改动**：
1. 欢迎性表述（包括“欢迎有育儿责任的父亲和母亲申请”）写明既不算 explicit_sex，也不算 care_condition。
2. 角色/声部写明“描述剧中角色或声音类型，不是应聘者性别限定”，只有另外写明限定应聘者本人时才单独列出。
3. 面向某一群体的培训或援助招募：scope 为 training，findings 为空。
4. 写明 JSON 的 6 个键名。

**污染声明**：新规则用了开发集原文措辞（“扮演成年男性角色”“女高音声部”“欢迎有育儿责任的父亲和母亲”“就业援助”）。因此 v2.1 在 role_voice、welcome、training 三个切片上的开发集结果**不能**说明泛化能力，只能用锁定测试集检验。没有新增示例。
