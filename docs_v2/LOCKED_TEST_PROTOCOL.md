# 锁定测试集协议 v0.1（草案，待负责人与法学联合研究者确认）

目的：在 Prompt、规则基线和评估脚本冻结后，用一批研发过程**从未见过**的文本做**一次**独立评估。

## 1. 为什么现有数据不能用

seed50、regression16、smoke14 和 probe6 都已经被提示词设计、规则编写或模型运行看过，只能作开发集。如果把它们同义改写后拿来当测试集，也不能算独立。

## 2. 角色与隔离

| 角色 | 做什么 | 不能做什么 |
|---|---|---|
| 出题人：法学联合研究者（可由负责人协助） | 写测试文本，独立标注 | 把文本或标签给 AI 工程侧（Claude）看；在研发会话里讨论具体条目 |
| AI 工程侧（Claude） | 提供冻结后的代码、提示词与哈希；收到输入文件后只跑一次 | 打开标签文件；看到输入后再改提示词；对同一测试集重复评估 |
| 负责人 | 保管标签；运行评估脚本，或监督其运行 | 在评估前把标签放进工作目录 |

AI 辅助：出题人可以用 ChatGPT 辅助写文本草稿，但需要在 `test_authoring_log` 中如实记录。不得使用 Claude 当前这个研发会话，也不得用 Spark 本身生成或筛选测试文本，否则就是对着被测模型挑题。

## 3. 内容要求

- 原创合成文本，不使用真实企业或个人信息。建议 60–100 条，以多句、较长的招聘公告为主。
- 不能是开发集条目的同义改写。程序检查：与任一开发集文本的字符 3-gram Jaccard ≥ 0.5 的条目要剔除，剔除数量要记录。
- 覆盖各类型，比例由出题人决定并事先写明：
  - 明确性别限定、优先、劝退
  - 婚育条件与询问
  - 照护条件
  - 语境暗示
  - 例外声明（unknown）
  - 否定、引用、历史条件
  - 角色与声部
  - 正常的能力要求
  - 专项培训
  - 多条件并存
  - 指令注入
- 标签字段与 `ANNOTATION_RULES.md` v1.0 相同：至少包括 triage、review_reason、scope、sex_link、care_condition、risk_quotes。允许标 `unresolved`。
- 最好有两人独立标注，记录分歧和裁决。只有一人标注时，要如实写明。

## 4. 存储与冻结步骤

1. 出题人生成两个文件：
   - `locked_inputs.jsonl`：只含 id 和 text。
   - `locked_labels.jsonl`。
2. 出题人计算两个文件的 SHA-256，把**哈希**发给负责人登记。登记的是哈希承诺，不发送文件。
3. 标签文件存放在工作目录之外。建议用加密 zip 或离线 U 盘保存，口令由负责人保管。
4. AI 工程侧运行 `scripts/freeze_v2.py`，记录以下内容的 SHA-256，生成 `FREEZE_v2.json`：
   - prompt 模块、契约与评估脚本、规则基线
   - 模型 revision 与生成参数
5. 负责人把 `FREEZE_v2.json` 与两个测试文件的哈希一起留存（可以发在群里或邮件里留时间戳）。
6. 负责人交付 `locked_inputs.jsonl`。AI 侧先校验它的哈希与登记一致，再对 Spark v2、基线 A、基线 B 各跑**一次**，并保存全部原始输出。
7. 负责人在工作目录外放入标签，运行 `scripts/evaluate_v2.py`。`label_source` 只有在标签由人冻结时才写 `human_frozen`。报告连同 `FREEZE_v2.json` 一起归档。
8. 评估后不得修改提示词再测一次。如需迭代，原测试集降级为开发集，重新出一套新的锁定集。

## 5. 报告口径

- 四分类混淆矩阵（含 invalid 列）
- 核心性别/婚育线索的 P/R：照护、语境、unknown 不计入
- 人工复核队列指标：单列，不得改名为“歧视识别率”
- 各类错误切片、证据子串有效率、JSON 通过率、延迟

结论只说明“在这批合成文本上”的表现，不外推到真实招聘，也不构成法律准确率。
