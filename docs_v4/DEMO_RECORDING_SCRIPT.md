# 演示视频录制脚本（约 4 分钟，由项目负责人本人录制）

**原则**：每一步都现场真实调用 Spark-X2.6-4B，不剪掉失败。如果某次输出和下面的“预期”不一样（云端有随机采样，这很正常），就**照实录下来并口头说明**，不要重录到“好看”为止。

## 录制前准备（不进画面）
1. 关掉无关的程序和浏览器标签，打开勿扰模式。画面里不要出现终端中的 Key、浏览器书签或聊天记录。
2. 如果已经轮换 Key：新 Key 写入 `~/.config/rfl/xfyun_api_key`（`chmod 600`）。
3. 启动服务：
```bash
cd rfl_stage1 && python3 mvp/server.py --provider xfyun_maas --replay outputs_v3/maas_v2.1_plus_pp2.3_dev86/records.jsonl --replay-raw outputs_v3/maas/dev86_v2.1_raw/raw.jsonl
```
4. 浏览器打开 http://127.0.0.1:8765 ，缩放 110%。先随便分析一句话做预热，这一步不录。
5. 准备好下面三段文本，录制时复制粘贴。

## 0:00–0:30 开场
- 画面：首页，停在顶部的提示条和模式说明行。
- 口播：这是“招聘公平镜”，给招聘信息审核人员用的复核辅助工具。它用 Spark-X2.6-4B 在招聘文本里找性别、婚育、照护相关条件，标出原文证据，告诉审核人缺什么事实。它**不判断是否违法，也不会自动举报**。现在调用的是讯飞星辰官方 API 上的 spark-x2.6-4b；云端的具体版本没有公开，采样有随机性。本地开源权重的运行记录我们也保留了。

## 0:30–1:30 场景 1：明确的婚育限制
- 粘贴：`【合成示例｜场景1】诚聘行政助理：本科学历，形象好；入职须签署承诺书，保证两年内不生育；已婚已育者优先。` 然后点“分析”。
- 预期：两条婚育线索，都是 flag，原文高亮，显示“法律结论：不判断”，列出白名单法源 S01、S02，并注明“适用性待法律审阅者确认”。
- 口播：模型找到了两处原文证据。程序会核对每一段引用是否是原文的原样片段。法源只从法学合作者核实过的清单里取，不让模型凭记忆写法条。
- 操作：两条都选“接受”，审核人填你自己的名字或角色，处理状态选“需法律进一步判断”，点“保存人工记录”，再点“导出审核记录 JSON”，在画面里打开导出的文件看一眼。
- 口播：最后由人来决定。导出的记录里保留了原文、模型的原始输出和人工修改。

## 1:30–2:40 场景 2：照护条件的不确定性
- 粘贴：`【合成示例｜场景2】招聘项目协调员：需每月出差约一周，男女均可；希望候选人没有育儿负担，能全身心投入。`
- 预期：育儿负担判为 review，显示“性别关联未建立”，附 3 个问发布方的核查问题；出差要求没有报警。
- 口播：“没有育儿负担”并不等于“不要女性”，男女都可能承担照护。工具不会推断性别，只提示这个条件和岗位的关系需要核实，并给出向发布方提问的问题，不要求求职者交代家庭情况。
- 操作：人工判断选“待补事实”，处理状态选“待补充材料”，然后保存。

## 2:40–3:40 场景 3：角色或声部（展示错误边界）
- 粘贴：`【合成示例｜场景3】城市合唱团招募女高音声部团员，按试唱和视唱能力选拔，欢迎有合唱经验者报名。`
- 预期（已知失败模式）：模型把女高音声部误判为性别限制；程序把它降为 review，并提示“可能是声部描述，需人工确认”。
- 口播：这是模型的已知错误。女高音是声部要求，不是限定应聘者性别。在我们 86 条开发样本里，同类句子模型 4 次全错。所以我们加了一个范围检查：只把它降为“需复核”，不替人做结论。
- 操作：选“拒绝（误报）”，人工分流改为 clear，处理状态选“更正语境误报”，然后保存。
- （可选）再粘贴 `招聘话剧演员：饰演剧中母亲一角，需为女性演员。`，说明一点：如果文本另外限定了应聘者本人的性别，仍然会判 flag。

## 3:40–4:20 结尾：局限与诚实说明
- 画面：切到 `docs_v4/DEMO_WALKTHROUGH.md` 或失败日志。
- 口播要点：
  - 现有的一致率数字（例如 78/86）来自开发集，标签是 AI 辅助的研究意见，**不是法律准确率**。独立的锁定测试由法学联合研究者出题，状态是【未完成 / 已完成，填写真实结果】。
  - 云端模型偶尔会输出格式错误的 JSON。程序只做有记录的修复，修复不了就交给人工，绝不当作“没问题”。
  - 团队有两位真人成员：负责人和法学联合研究者。Claude 和 ChatGPT 是开发辅助工具，不是团队成员。

## 录完后
- 视频建议上传到 Bilibili 或 YouTube，设为公开或“仅链接可见”，然后在 HF Discussion 中嵌入链接。
- 录制中真实点了“保存”，会在 `mvp/logs/` 里留下由你本人署名的审核记录，这些是真实操作，可以保留。
